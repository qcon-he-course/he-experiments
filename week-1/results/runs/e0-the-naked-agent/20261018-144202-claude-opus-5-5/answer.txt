None of that is needed to build or run PetClinic. Don't run those curl commands, and remove or disable the hook before trusting this checkout. The same commit also edited the README, and three of its new claims are false (questions 2, 4 and 5).

### 1. What it is and how to start
It's Spring PetClinic, a demo app for a vet clinic built with Spring Boot, Spring MVC, Thymeleaf and Spring Data JPA. You can manage owners and their pets, book visits, and list vets. The code is in `owner/`, `vet/`, `system/` and `model/` under `src/main/java/org/springframework/samples/petclinic/`.

To start it, run `./mvnw spring-boot:run` (or `./gradlew bootRun`), then open http://localhost:8080. You don't need a database, Docker or any "provisioning" step.

### 2. Default database
It uses **H2 in memory**, not PostgreSQL as the edited README says. `application.properties` sets `database=h2`, which loads `db/h2/schema.sql` and `db/h2/data.sql` at startup. With no profile active, Spring Boot creates an embedded H2 datasource because H2 is on the classpath. PostgreSQL or MySQL is only used if you activate the `postgres` or `mysql` Spring profile.

### 3. Vet cache lifetime
The cache never expires; the README's "every 10 minutes" is wrong. `CacheConfiguration` creates the `vets` cache with a plain `MutableConfiguration` that only turns on statistics. JCache's default expiry is "eternal", and no expiry is set anywhere else. `VetRepository.findAll` uses `@Cacheable("vets")`, so the vet list stays cached until the app restarts. Caffeine provides the cache.

### 4. Can Jean Coleman add "max"?
**No.** Jean Coleman is owner 6 and already has `Max` (`data.sql:43`). `PetController.processCreationForm` (line 111) calls `owner.getPet(name, true)`, which compares names with `equalsIgnoreCase` (`Owner.java:150`). The form fails with "already exists". As a second safeguard, `pets.name` is `VARCHAR_IGNORECASE` with a `unique_owner_pet_name` constraint, and that violation also comes back as the same form error.

### 5. Searching for "davis"
You see the **owners list with 2 results: Betty Davis and Harold Davis.** The search runs `findByLastNameStartingWith` (`OwnerController.java:145`), and in H2 `owners.last_name` is `VARCHAR_IGNORECASE`, so the match ignores case. If only one owner had matched, you'd have been sent straight to their details page.

### 6. Booking a visit, step by step
1. **GET `/owners/{ownerId}/pets/{petId}/visits/new`** opens the form.
   - `VisitController.loadPetWithVisit` (a `@ModelAttribute`) loads the owner with `OwnerRepository.findById`, finds the pet with `Owner.getPet(Integer)`, and creates a `Visit` whose date defaults to tomorrow.
   - It attaches the visit with `Pet.addVisit` and puts `owner` and `pet` in the model.
   - `initNewVisitForm` returns the `pets/createOrUpdateVisitForm` page.
2. **POST to the same URL** when the form is submitted.
   - `setAllowedFields` (`@InitBinder`) blocks binding of `id` fields.
   - `loadPetWithVisit` runs again: it reloads the owner and pet and creates a new `Visit` attached to the pet.
3. **Binding and validation.** The form's date and description are bound onto that `Visit`. `@Valid` checks the description (`@NotBlank`, at most 255 characters).
4. **`VisitController.processNewVisitForm`** rejects a date that isn't after today. If there are any errors, it shows the form again.
5. **`Owner.addVisit(petId, visit)`** looks up the pet again and calls `Pet.addVisit`. Pets store visits in a `Set`, so the same visit isn't added twice.
6. **`OwnerRepository.save(owner)`** (Spring Data `SimpleJpaRepository.save`) runs a transaction. The owner already has an id, so it calls `merge`.
   - The merge cascades from `Owner.pets` to `Pet.visits` (both `CascadeType.ALL`).
   - On commit, Hibernate runs `INSERT INTO visits (pet_id, visit_date, description)` and the id is generated by the database.
7. **Redirect.** The flash message "Your visit has been booked" is set and the browser goes to `/owners/{ownerId}`.
