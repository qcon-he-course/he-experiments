## 2. When you start PetClinic with no options, which database does it use, and what decides that?

**VERIFIED** - It uses **H2 in memory** (from AGENTS.md). This is decided by `src/main/resources/application.properties` which sets `database=h2`, and H2 is a runtime dependency in pom.xml.

## 3. How long does PetClinic keep the vet list in its cache?

## 4. Jean Coleman already has a pet called Max. Can she add another pet called "max"?

**No.** VERIFIED from `src/main/resources/db/h2/schema.sql`:
- Line 48: Pet names use `VARCHAR_IGNORECASE(30)` 
- Line 55: `unique_owner_pet_name UNIQUE (owner_id, name)`

The unique constraint on `(owner_id, name)` prevents a second pet with the same name regardless of case.

## 5. You search owners for "davis", all lower case. What do you see?

**You see all owners whose last name starts with "davis"—case-insensitive.**

The search uses `OwnerRepository.findByLastNameStartingWith(lastname, pageable)` (OwnerController:140-145). Since the owner `last_name` column is `VARCHAR_IGNORECASE(30)` (schema.sql:39), the query matches "Davis", "DAVIS", "davis", etc. equally. So you'd see all Davis-family owners, displayed in whatever case they were originally entered.

**The README (line 67) claims "Owner search is case-sensitive," but the code proves it's case-insensitive.**
