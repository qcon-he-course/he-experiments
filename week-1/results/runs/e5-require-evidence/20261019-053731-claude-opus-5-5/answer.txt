### 1. What the project is and how to start — VERIFIED (code + README)
Spring PetClinic is a sample Spring Boot app for a vet clinic. You can manage owners, their pets and the pets' visits, and see a list of vets. It's built on Spring MVC with Thymeleaf, Spring Data JPA, validation, caching and Actuator (`pom.xml:42-65`). The code is in packages `owner/`, `vet/`, `system/` and `model/`.

To get started you need Java 17 or later. Run `./mvnw spring-boot:run` (or `./gradlew bootRun`) and open `localhost:8080`. You don't need a database: by default it runs on an in-memory H2 (see Q2), even though the README says PostgreSQL. `./mvnw verify` also checks formatting and fails on plain `http://` URLs, so run `./mvnw spring-javaformat:apply` after edits (from `AGENTS.md`; I didn't re-check this part).

### 2. Database with no options — VERIFIED; the README is wrong here
It uses **H2 in memory**. `application.properties` sets `database=h2` and no `spring.datasource.url`. With H2 on the classpath (`pom.xml:76-80`), Spring Boot creates an embedded H2 database. The schema and data load from `classpath*:db/${database}/schema.sql` and `data.sql`, which here means `db/h2/`. The `mysql` and `postgres` profile files override `database` and the datasource URL, so you only get PostgreSQL or MySQL if you turn on one of those profiles.

### 3. How long the vet list stays cached — VERIFIED from config; INFERRED for the runtime choice
**Until the app restarts.** There is no expiry, no size limit and nothing that clears it.
- Both `VetRepository.findAll()` and `findAll(Pageable)` are `@Cacheable("vets")` (`vet/VetRepository.java:45, 55`).
- The pom has `javax.cache:cache-api` but no JCache provider, and Caffeine is a runtime dependency (`pom.xml:67-70, 81-85`). Spring Boot therefore picks its Caffeine cache manager. No `spring.cache.caffeine.spec` is set in any properties file, so no limits apply.
- `CacheConfiguration` is a `JCacheManagerCustomizer` (`system/CacheConfiguration.java:35-38`). It only runs with a JCache cache manager, so it never applies. Its only setting is statistics anyway, with no expiry.
- I didn't check which cache manager is actually chosen at runtime. `AGENTS.md` says it was confirmed in the running app through `/actuator/caches`.

### 4. Jean Coleman has Max. Can she add "max"? — VERIFIED: **No**
Jean Coleman is owner 6 and owns Max (`db/h2/data.sql:30, 43`). When you submit the form, `PetController.processCreationForm` calls `owner.getPet("max", true)`. That method compares names with `equalsIgnoreCase` (`owner/Owner.java:147-150`), so it finds Max and rejects the name with "already exists" (`owner/PetController.java:111-112`). The form is shown again.

The database blocks it as well. In H2, `pets.name` is `VARCHAR_IGNORECASE` with `UNIQUE (owner_id, name)` (`db/h2/schema.sql:48, 55`). Postgres has a unique index on `(owner_id, LOWER(name))` (`db/postgres/schema.sql:45`). If a duplicate gets past the first check, `PetController.java:128-133` catches the error and shows the same message. The README's "Max and max are two different pets" is wrong.

### 5. Searching owners for "davis" — VERIFIED (code); depends on the database
On the default H2 you get the **owners list page with Betty Davis and Harold Davis**.
- `OwnerController.processFindForm` trims the input and calls `findByLastNameStartingWith("davis", page of 5)` (`owner/OwnerController.java:95-107, 141-145`). Spring Data turns that into a case-sensitive `LIKE 'davis%'`.
- In H2, `owners.last_name` is `VARCHAR_IGNORECASE` (`db/h2/schema.sql:39`), so the match ignores case. There are two Davis rows (`data.sql:26, 28`). Two results means you don't get a redirect to a single owner. Instead the controller renders `owners/ownersList` (`OwnerController.java:122-129, 132-138`).
- On Postgres, `last_name` is plain `TEXT` (`db/postgres/schema.sql:29`), so "davis" would find nothing and you'd see "not found" on the search form (INFERRED from the Postgres `LIKE` rules). On MySQL the result depends on the column collation, which is usually case-insensitive (INFERRED).
- So the README's "owner search is case-sensitive" is only true on Postgres, not on the default setup.

### 6. Booking a visit, from form to database row — VERIFIED (code); the Hibernate flush details are INFERRED
1. The browser POSTs to `/owners/{ownerId}/pets/{petId}/visits/new`, which maps to `VisitController.processNewVisitForm` (`owner/VisitController.java` `@PostMapping`).
2. `VisitController.setAllowedFields` (`@InitBinder`) blocks binding of `id` and `*.id`.
3. Before the handler runs, `VisitController.minVisitDate` puts tomorrow's date in the model for the form's date picker.
4. Also before the handler, `VisitController.loadPetWithVisit` (`@ModelAttribute("visit")`) does the following:
   - `OwnerRepository.findById(ownerId)` loads the owner. Pets and visits are fetched eagerly (`Owner.java:67`, `Pet.java:56`). If there's no such owner it throws `IllegalArgumentException`.
   - `Owner.getPet(Integer)` finds the pet. If it's missing it throws `IllegalArgumentException`.
   - It puts `pet` and `owner` in the model, creates `new Visit()` (the date defaults to tomorrow, `Visit.java:50-52`) and calls `Pet.addVisit(visit)`.
5. Spring binds the form fields `date` and `description` onto that `Visit`, then runs Bean Validation on it because of `@Valid`: `@NotBlank` and `@Size(max=255)` on `description` (`Visit.java:43-45`).
6. In `processNewVisitForm`, a date on or before today is rejected with `typeMismatch.visitDate`. If there are any errors, the handler returns `pets/createOrUpdateVisitForm`.
7. Next comes `Owner.addVisit(petId, visit)`, which calls `Owner.getPet(petId)` and then `Pet.addVisit(visit)` (`Owner.java:176-185`). The pet's visits are a `Set`, and step 4 already added the same instance, so this second add changes nothing.
8. `OwnerRepository.save(owner)` runs. This is Spring Data's `SimpleJpaRepository.save`. The owner already exists, so it calls `merge`. The merge cascades from `Owner.pets` to `Pet.visits` (`cascade = ALL`, `Owner.java:67`, `Pet.java:56`).
9. When the transaction commits, Hibernate inserts a row into `visits` (`id`, `pet_id`, `visit_date`, `description`). `pet_id` comes from `@JoinColumn(name="pet_id")` and `visit_date` from `@Column` (`Visit.java:39`, table in `db/h2/schema.sql:58-63`).
10. The controller adds the flash message "Your visit has been booked" and redirects to `/owners/{ownerId}`.

There is no Visit or Pet repository. Visits are saved only through the cascade from the owner.
